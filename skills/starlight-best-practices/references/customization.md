## Overriding components

```js
// astro.config.mjs
starlight({
  title: 'My Docs',
  components: {
    SocialIcons: './src/components/EmailLink.astro',
  },
});
```

```astro
---
// src/components/EmailLink.astro
import Default from '@astrojs/starlight/components/SocialIcons.astro';
---

<a href="mailto:hello@example.com">Email us</a>
<Default><slot /></Default>
```

- Use component names from `https://starlight.astro.build/reference/overrides/`. The key is `SocialIcons`, not `SocialLinks`.
- Reuse the built-in component by importing it from `@astrojs/starlight/components/<Name>.astro` and rendering `<Default><slot /></Default>`. Do not spread `Astro.props` into it.
- `PageFrame` and `TwoColumnContent` have named slots. Pass them through: `<slot name="right-sidebar" slot="right-sidebar" />`.
- A `PageTitle` override must keep `id="_top"` on the `<h1>`.
- To override on some pages only, branch on route data and render the default otherwise.

## Route data

Page data is on `Astro.locals.starlightRoute` in any component rendered on a Starlight page:

```astro
---
const { id, entry, sidebar, toc, hasSidebar, lang, siteTitle } = Astro.locals.starlightRoute;
const isHomepage = id === '';
---

<p>{Astro.locals.t('search.label')}</p>
```

- `Astro.locals.t()` returns UI strings for the current locale.
- The type is `StarlightRouteData` from `@astrojs/starlight/route-data`. The older `@astrojs/starlight/props` module is deprecated.

To change route data before a page renders, add a route middleware:

```js
// astro.config.mjs
starlight({
  title: 'My Docs',
  routeMiddleware: './src/routeData.ts',
});
```

```ts
// src/routeData.ts
import { defineRouteMiddleware } from '@astrojs/starlight/route-data';

export const onRequest = defineRouteMiddleware((context) => {
  const { entry } = context.locals.starlightRoute;
  entry.data.title = entry.data.title + '!';
});
```

The file must not be `src/middleware.ts` or `src/middleware/index.ts`. Guide: `https://starlight.astro.build/guides/route-data/`.

## Custom pages

Pages outside the docs collection go in `src/pages/` and use the `StarlightPage` component for the Starlight layout:

```astro
---
// src/pages/changelog.astro
import StarlightPage from '@astrojs/starlight/components/StarlightPage.astro';
---

<StarlightPage frontmatter={{ title: 'Changelog' }}>
  <p>Custom content.</p>
</StarlightPage>
```

- `frontmatter` is required and needs `title`. Other props: `sidebar`, `hasSidebar`, `headings` (for a table of contents), `lang`, `dir`.
- These pages are not in the docs collection. Link to them from the sidebar with `{ label, link }`; they cannot appear in an autogenerated group, and `slug` and `draft` exclusion do not apply to them.
- For a custom 404 page as an Astro file, set `disable404Route: true`. Otherwise add `src/content/docs/404.md`.
- Markdown in `src/pages/` does not get Starlight's asides or heading links unless its directory is listed in `markdown.processedDirs`.

## CSS

```js
starlight({
  title: 'My Docs',
  customCss: ['./src/styles/custom.css'],
});
```

```css
/* src/styles/custom.css */
:root {
  --sl-content-width: 50rem;
  --sl-color-accent: #6d28d9;
}
```

- Starlight's styles are in the `starlight` cascade layer. Unlayered custom CSS overrides them without `!important`. To order your own layers around it: `@layer my-reset, starlight, my-overrides;`.
- Theme with Starlight's `--sl-*` custom properties before writing selector overrides.
- Since Starlight 0.43, scoped styles use Astro's default `attribute` strategy. A `class` passed to a child component no longer carries the parent's scope; set `scopedStyleStrategy: 'where'` in the Astro config only if existing styles depend on the old behaviour.

## Tailwind

Starlight supports Tailwind 4 only. Run `npx astro add tailwind`, install `@astrojs/starlight-tailwind`, then:

```css
/* src/styles/global.css */
@layer base, starlight, theme, components, utilities;
@import '@astrojs/starlight-tailwind';
@import 'tailwindcss/theme.css' layer(theme);
@import 'tailwindcss/utilities.css' layer(utilities);
```

```js
// astro.config.mjs
import { defineConfig } from 'astro/config';
import starlight from '@astrojs/starlight';
import tailwindcss from '@tailwindcss/vite';

export default defineConfig({
  integrations: [
    starlight({
      title: 'Docs with Tailwind',
      customCss: ['./src/styles/global.css'],
    }),
  ],
  vite: { plugins: [tailwindcss()] },
});
```

- Do not use `@import 'tailwindcss'` in this file; it loads Tailwind's full reset over Starlight's styles.
- Set theme colours and fonts in CSS with `@theme { --color-accent-*: ...; --color-gray-*: ...; --font-sans: ...; }`. There is no `tailwind.config` plugin.

Guide: `https://starlight.astro.build/guides/css-and-tailwind/`.

## Plugins

```ts
// plugin.ts
export default {
  name: 'my-plugin',
  hooks: {
    'i18n:setup'({ injectTranslations }) {
      injectTranslations({
        en: { 'myPlugin.doThing': 'Do the thing' },
      });
    },
    'config:setup'({ config, updateConfig, addRouteMiddleware }) {
      updateConfig({
        social: [
          ...(config.social ?? []),
          { icon: 'github', label: 'GitHub', href: 'https://github.com/withastro/starlight' },
        ],
      });
      addRouteMiddleware({ entrypoint: 'my-plugin/middleware' });
    },
  },
};
```

- The hook is `'config:setup'`. The earlier `setup` name is deprecated.
- `injectTranslations` is only available in `'i18n:setup'`.
- `updateConfig` takes top-level Starlight options and replaces each given key. Spread the existing value (`config.social`) to extend an array or nested object.
- Other `'config:setup'` options: `addIntegration`, `astroConfig`, `command`, `isRestart`, `logger`, `useTranslations`, `absolutePathToLang`. Type hook arguments with `HookParameters` from `@astrojs/starlight/types`.

Reference: `https://starlight.astro.build/reference/plugins/`.
