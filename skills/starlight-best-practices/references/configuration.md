## Project setup

- New site: `npm create astro@latest -- --template starlight` (variants: `starlight/tailwind`, `starlight/markdoc`).
- Existing Astro project: `npx astro add starlight`.
- Upgrade: `npx @astrojs/upgrade`, which moves Astro and Starlight together.

```js
// astro.config.mjs
import { defineConfig } from 'astro/config';
import starlight from '@astrojs/starlight';

export default defineConfig({
  integrations: [
    starlight({
      title: 'My delightful docs site',
      social: [{ icon: 'github', label: 'GitHub', href: 'https://github.com/withastro/starlight' }],
      sidebar: [
        {
          label: 'Guides',
          items: [{ label: 'Example Guide', slug: 'guides/example' }],
        },
        {
          label: 'Reference',
          items: [{ autogenerate: { directory: 'reference' } }],
        },
      ],
    }),
  ],
});
```

Required files: `astro.config.mjs`, `src/content.config.ts`, and `src/content/docs/index.md` or `index.mdx`.

Starlight adds `@astrojs/mdx`, `@astrojs/sitemap` and `astro-expressive-code` itself. Do not add them to `integrations`.

## Content collections

```ts
// src/content.config.ts
import { defineCollection } from 'astro:content';
import { docsLoader, i18nLoader } from '@astrojs/starlight/loaders';
import { docsSchema, i18nSchema } from '@astrojs/starlight/schema';

export const collections = {
  docs: defineCollection({ loader: docsLoader(), schema: docsSchema() }),
  // Optional: only needed to translate UI strings
  i18n: defineCollection({ loader: i18nLoader(), schema: i18nSchema() }),
};
```

- `docsLoader()` loads Markdown, MDX and Markdoc from `src/content/docs/`. There is no option to change the directory or add a route prefix; to serve docs under `/guides/`, nest the files in `src/content/docs/guides/`.
- File names are slugified: lowercased, with special characters removed (`Example.File.md` is served at `/examplefile`). Pass `docsLoader({ generateId })` to change this.
- Extend the frontmatter schema with `docsSchema({ extend })`:

```ts
import { z } from 'astro/zod';

docsSchema({
  extend: z.object({
    // Make a built-in field required
    description: z.string(),
    // Add a new field
    category: z.enum(['tutorial', 'guide', 'reference']).optional(),
  }),
});
```

For image fields use the function form: `extend: ({ image }) => z.object({ cover: image() })`.

## Sidebar

Item forms, all valid inside the top-level array or a group's `items`:

| Form | Use |
| --- | --- |
| `'guides/intro'` | Link to a docs page by ID; the label comes from the page title |
| `{ slug: 'guides/intro' }` | Same, with room for `label`, `badge`, `attrs`, `translations` |
| `{ label: 'Astro', link: 'https://astro.build/' }` | External URL or a page outside the docs collection |
| `{ label: 'Guides', items: [...], collapsed: true }` | Group |
| `{ autogenerate: { directory: 'reference', collapsed: true } }` | Every page in a directory. Only valid inside a group's `items` |

- A `slug` is the page ID: no leading or trailing slash, `'index'` for the root. A slug with no matching page fails the build. Draft pages are excluded from production builds and cannot be referenced by slug.
- Autogenerated subgroups are expanded by default; set `collapsed` inside `autogenerate` to collapse them. They do not inherit the parent group's `collapsed`.
- Order and label autogenerated links from page frontmatter: `sidebar: { label, order, hidden, badge }`. This frontmatter also applies to `slug` links, not to `link` items.
- `badge` is a string or `{ text, variant, class }`.

With no `sidebar` option, Starlight generates one from the directory structure.

## Social links, head and favicon

```js
starlight({
  social: [
    { icon: 'github', label: 'GitHub', href: 'https://github.com/withastro/starlight' },
    { icon: 'discord', label: 'Discord', href: 'https://astro.build/chat' },
  ],
  favicon: '/favicon.svg', // a path under public/
  head: [
    { tag: 'meta', attrs: { property: 'og:image', content: 'https://example.com/og.png' } },
    { tag: 'script', attrs: { src: 'https://example.com/analytics.js', defer: true } },
  ],
});
```

- `social` is an array. `icon` is any built-in Starlight icon name.
- `head` entries are emitted as written. They are not processed by Astro, so they cannot import local modules; override the `Head` component for that. For `meta` tags, `content` goes inside `attrs`.
- Per-page head tags go in the page's `head` frontmatter.

## Internationalisation

```js
starlight({
  title: 'My Docs',
  defaultLocale: 'root',
  locales: {
    // English pages in src/content/docs/
    root: { label: 'English', lang: 'en' },
    // Simplified Chinese pages in src/content/docs/zh-cn/
    'zh-cn': { label: '简体中文', lang: 'zh-CN' },
  },
});
```

- Keys of `locales` are directory names. The `root` locale needs `lang`. `defaultLocale` must be a key of `locales`.
- A single-language site that is not English sets `locales: { root: { label: 'Deutsch', lang: 'de' } }`.
- Use the same file name in every locale directory. A missing translation falls back to the default locale's page with a notice.
- UI string translations live in `src/content/i18n/<lang>.json` and need the `i18n` collection defined.
- A translated site title is keyed by language tag: `title: { en: 'My Docs', 'zh-CN': '我的文档' }`.

Guide: `https://starlight.astro.build/guides/i18n/`.

## Search

Pagefind search is on by default and is built during `astro build`. It does not work in `astro dev`.

- Exclude a page with `pagefind: false` in its frontmatter, or part of a page with a `data-pagefind-ignore` attribute.
- `prerender: false` (rendering docs pages on demand) disables Pagefind; the two cannot be combined.
- Algolia DocSearch is available through `@astrojs/starlight-docsearch`.

## Other options

- `customCss: ['./src/styles/custom.css']`: paths under `src/` or npm package names.
- `editLink: { baseUrl: 'https://github.com/org/repo/edit/main/docs/' }`.
- `lastUpdated: true`: uses git history; fetch full history in CI.
- `tableOfContents: false` or `{ minHeadingLevel: 2, maxHeadingLevel: 3 }`.
- `expressiveCode`: `false` or an options object for code block themes and behaviour.
- `markdown: { headingLinks: false }` turns off heading anchor links. `markdown: { processedDirs: ['./src/data/reviews/'] }` applies Starlight's Markdown features to content outside the docs collection.
- `components`, `routeMiddleware`, `plugins`: see [customization](customization.md).
